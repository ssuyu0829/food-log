# 設定說明

從零到能用，大約 40 分鐘。**照順序做，每一步都有「怎麼確認成功」。**

全部在免費額度內：Supabase free、Gemini free tier、Telegram、GitHub Pages。
需要四個帳號：Google、Telegram、Supabase、GitHub。

> **這個系統是單人用的。** 一個部署只服務一個 Telegram 帳號、一支手機。
> 要給第二個人用，就照這份文件再部署一份（各自一個 Supabase 專案與 Bot）。

## 步驟 0 — 把程式拿下來

1. 在 GitHub 上 **Fork** 這個 repo 到你自己的帳號（步驟 7 的 GitHub Pages 要從你自己的 repo 發布）
2. clone 到本機：

```bash
git clone https://github.com/<你的帳號>/food-log.git
cd food-log
```

之後所有指令都在這個目錄裡跑。

---

## 步驟 1 — 拿 Gemini API key（3 分鐘）

1. 到 <https://aistudio.google.com/apikey>，用 Google 帳號登入
2. **Create API key** → 選一個 Google Cloud 專案（沒有就讓它幫你建）
3. 複製金鑰，先貼在記事本

> ⚠️ 免費層的內容（也就是你的食物照片）Google 可能會用來改善模型。
> 介意的話，在同一頁把專案升級成付費層（用量這麼小幾乎不會產生費用），
> 或改用其他模型 API——只要改 `supabase/functions/_shared/gemini.ts` 一個檔。

**確認成功**：金鑰是 **`AQ.` 開頭**、約 50 個字元。
（2026-09 起新申請的 key 都是這個格式，不再是舊文件常見的 `AIza`。）

---

## 步驟 2 — 開 Telegram Bot（3 分鐘）

1. Telegram 搜尋 `@BotFather`，或直接點 <https://t.me/BotFather> 開對話
2. 傳 `/newbot`
3. 取一個顯示名稱（例如「飲食帳本」）
4. 取一個 username，**必須以 `bot` 結尾**（例如 `myname_foodlog_bot`）
5. BotFather 會回一串 `123456789:AAxxxxxxxx` 的 token，複製起來

順便設一下選單（可跳過）：傳 `/setcommands` → 選你的 bot → 貼上：

```
today - 今天吃了什麼
week - 本週回顧
again - 再來一份（從最近吃過的挑一個直接記）
target - 設每日熱量目標
limit - 設每週手搖上限
weight - 看體重曲線
calib - 由體重反推熱量校準
tdee - 設參考 TDEE
protein - 設蛋白質倍率（g/kg）
undo - 刪掉最後一筆
app - 拿報表網址
```

**確認成功**：你手上有兩串東西——Gemini key 和 Bot token。

---

## 步驟 3 — 開 Supabase 專案（5 分鐘）

1. <https://supabase.com/dashboard/new> → 用 GitHub 登入 → **New project**
   （專案列表在 <https://supabase.com/dashboard/projects>）
2. 名字 `food-log`，區域選 **Northeast Asia (Tokyo)**
3. 設一個資料庫密碼（存起來，之後用不太到）
4. **Security 三個選項這樣勾**：

   | 選項 | 怎麼做 | 為什麼 |
   |---|---|---|
   | Enable Data API | ✅ **保持勾選** | Edge Function 的 `db.ts` 用 supabase-js 的 `.from()`，走的就是這個 API。**關掉整包會壞。** |
   | Automatically expose new tables | ✅ **保持勾選** | 關掉會讓 `schema.sql` 建的表沒有 GRANT 給 service_role，Edge Function 直接吃 `42501 permission denied`、bot 完全不動。若已經關掉，跑 `supabase/fix_grants.sql` 補救。 |
   | Enable automatic RLS | ✅ **勾起來** | `schema.sql` 本來就把所有表 RLS 全開且不建 policy；勾這個等於多一層保險。service_role 會繞過 RLS，Edge Function 照常運作。 |

   ⚠️ Region 記得展開確認選到 **Northeast Asia (Tokyo)**——
   下拉可能先顯示「Asia-Pacific」這個大分類，那不是最終選擇。
5. 等 2 分鐘建好

> 開一個**專屬的新專案**，不要跟你其他專案共用資料庫：
> `schema.sql` 會對整個 `public` schema 做 GRANT 與 RLS 設定。

### 建資料表

1. 左側 **SQL Editor** → New query
   （直達：`https://supabase.com/dashboard/project/<PROJECT_REF>/sql/new`）
2. 貼上 `supabase/schema.sql` 整份 → **Run**
3. 最下面會印出一串 32 字元的 **PWA token**，複製起來（步驟 7 要用）
4. 再開一個 New query，貼上 `supabase/seed_drinks.sql` → **Run**

> `supabase/` 裡還有兩份 `alter_2026-09-*.sql`，那是給**舊安裝升級**用的，
> 新裝**不要跑**，`schema.sql` 已經包含同樣的欄位。

**確認成功**：左側 **Table Editor** 看得到 `meals`、`meal_items`、`drinks`、
`settings`、`report_token`、`weights` 六張表，其中 `drinks` 有 50 幾筆資料。

### 抄下三個值

左側 **Settings → API Keys**
（直達：`https://supabase.com/dashboard/project/<PROJECT_REF>/settings/api-keys`；
舊文件寫的 `/settings/api` 已經改到這裡）：

| 名稱 | 長相 | 用途 |
|---|---|---|
| Project URL | `https://xxxx.supabase.co` | 步驟 7 的 PWA 要用 |
| Project ref | 上面網址中的 `xxxx` | 步驟 4 要用 |
| service_role | `eyJ...`（很長） | 步驟 4 與步驟 8 要用 |

> 🔴 **service_role 等同資料庫最高權限。** 它只能出現在
> Supabase 的 Secrets 與 SQL Editor 裡，**永遠不要**進 git、不要進 `pwa/` 資料夾。

## 步驟 4 — 部署 Edge Functions（10 分鐘）

需要 Supabase CLI。裝法擇一：

```bash
# macOS / Linux（Homebrew）
brew install supabase/tap/supabase

# Windows（Scoop）
scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase

# 任何有 Node.js 的環境：不安裝，直接用 npx
npx supabase@latest --version      # 之後所有 supabase 指令前面加 npx
```

裝好用 `supabase --version` 確認。
（Deno 只有跑測試與本機假資料伺服器才需要，部署不用。）

```bash
# 登入（會開瀏覽器）
supabase login

# 綁到你剛建的專案，<PROJECT_REF> 換成步驟 3 抄的那串
supabase link --project-ref <PROJECT_REF>
```

### 設定金鑰

先想一個 webhook 密語（隨便一串英數字，例如 `myfoodlog2026xyz`），
這是用來確認打進來的請求真的是 Telegram，不是別人亂送的。

```bash
supabase secrets set \
  TELEGRAM_BOT_TOKEN="步驟2的token" \
  GEMINI_API_KEY="步驟1的金鑰" \
  TELEGRAM_WEBHOOK_SECRET="你想的密語"
```

> `SUPABASE_URL` 與 `SUPABASE_SERVICE_ROLE_KEY` 是 Supabase 自動注入的，不用自己設。

### 部署

```bash
# 對外的兩支（Telegram 與瀏覽器打不出 JWT）
supabase functions deploy telegram-webhook report --no-verify-jwt --use-api

# 排程用的兩支（cron 會帶 service_role，驗得過，要保留驗證）
supabase functions deploy daily-summary weekly-report --use-api
```

⚠️ **一定要分成兩行，不要四支寫在同一行加 `--no-verify-jwt`。**
那個 flag 會套用到**該次列出的每一支**，等於把 `daily-summary` / `weekly-report`
也開放給任何知道網址的人打。這個坑真的發生過：四支的 `verify_jwt` 全變成 false。

⚠️ **`--use-api` 是給沒裝 Docker 的機器用的**（在雲端打包）。有 Docker 可以拿掉。

**確認成功**：

```bash
supabase functions list -o json | python3 -c "
import sys,json
d=json.load(sys.stdin)
for f in (d['functions'] if isinstance(d,dict) else d):
    print(f\"{f['slug']:<18}v{f['version']}  verify_jwt={f['verify_jwt']}\")"
```

應該看到 `telegram-webhook` / `report` 是 **false**，
`daily-summary` / `weekly-report` 是 **true**。

## 步驟 5 — 接上 Telegram（2 分鐘）

把下面三個值換掉後，在終端機執行：

```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<PROJECT_REF>.supabase.co/functions/v1/telegram-webhook",
    "secret_token": "<你想的密語>",
    "allowed_updates": ["message", "callback_query"]
  }'
```

**確認成功**：回傳 `{"ok":true,...,"description":"Webhook was set"}`

想確認狀態：`curl "https://api.telegram.org/bot<BOT_TOKEN>/getWebhookInfo"`
（`pending_update_count` 應該是 0，`last_error_message` 應該沒有）

## 步驟 6 — 綁定並試用（5 分鐘）

1. Telegram 打開你的 bot，傳 **`/start`**
   → 它會回「綁定完成」。**這一步決定了誰是主人，別人傳 `/start` 會被拒絕。**
2. 傳一張你正在吃的東西的照片
   → 30 秒內應該回你逐項熱量 + 幾個修正按鈕
3. 傳文字：`50嵐 四季春 微糖 大`
   → 應該秒回（走本地熱量表，不呼叫 AI）
4. 傳 `/today` → 看到今天的統計

### 建議做一次的準確度抽驗

挑 **3 樣熱量已知**的東西各拍一張，比對 AI 給的數字：

- 一個有營養標示的包裝食品（例如超商飯糰）
- 一個超商便當（盒上有標示）
- 一杯查得到官方熱量表的手搖

誤差如果超過 40%，調整 `supabase/functions/_shared/gemini.ts` 裡 `SYSTEM` prompt 的
份量規則（第 3、7 條），重新部署 `telegram-webhook` 後再測一次。

**確認成功**：Supabase → Table Editor → `meals` 看得到剛剛那幾筆。

## 步驟 7 — 上線 PWA（10 分鐘）

### 填 API 網址

編輯 `pwa/config.js`。**這一行目前填的是原作者的專案**，一定要換成你自己的
project ref（步驟 3 抄的那個），否則 PWA 會去打別人的伺服器：

```js
window.FOODLOG_CONFIG = {
  API_BASE: "https://<PROJECT_REF>.supabase.co/functions/v1",
};
```

### 推到 GitHub Pages

```bash
git add -A
git commit -m "換成自己的 Supabase 專案"
git push
```

> ⚠️ GitHub Pages 的**免費方案不支援 private repo**。
> 兩個選擇：
> 1. 把 repo 設成 public——**可以**，因為這個 repo 裡沒有任何金鑰，
>    而且 PWA 沒有 token 就讀不到任何資料
> 2. 保持 private，改用 Cloudflare Pages / Netlify（都有免費方案且支援 private）

設成 public + Pages：GitHub 網頁 → **Settings → Pages** → Source 選 `main` 分支、資料夾選 `/pwa`
（如果選項只有 `/` 與 `/docs`，就把 `pwa/` 的內容移到 repo 根目錄）。

網址會是 `https://<你的帳號>.github.io/food-log/`

### 把網址與 token 存回資料庫

Supabase SQL Editor：

```sql
-- ⚠️ 網址一定要連 ?t=<PWA_TOKEN> 一起填。只填網域的話，
-- 手機打開會停在「這台裝置還沒認證，請用 /app 拿帶 ?t= 的網址」，
-- 而 /app 給的就是這個沒 token 的網址 —— 繞成死結。
update settings set value = 'https://<你的帳號>.github.io/food-log/?t=<PWA_TOKEN>' where key = 'pwa_url';
```

### 在手機上加到主畫面

- **iPhone**：用 **Safari**（Chrome 不行）開
  `https://<你的帳號>.github.io/food-log/?t=<PWA_TOKEN>` → 下方分享鈕 → **加入主畫面**
- **Android**：用 Chrome 開同一條網址 → 右上選單 → **加到主畫面**

token 會存進這台裝置，之後從圖示打開就不用再帶。

**確認成功**：主畫面出現朱紅印章圖示，點開是全螢幕、看得到今天的數字。

## 步驟 8 — 開啟每日／每週推播（5 分鐘）

1. 打開 `supabase/cron.sql`
2. 把 `<PROJECT_REF>` 與 `<SERVICE_ROLE>` 換成你的值
3. **不要存檔回 git**——直接複製內容貼進 Supabase SQL Editor → Run
   （或另存成 `supabase/cron.local.sql`，這個檔名已經在 `.gitignore` 裡）

時間已經設成台北 21:30（每日）與週日 20:00（每週）。

**先手動測一次**，不要等到晚上才發現壞掉。
CLI 已經移除 `functions invoke`，改成直接打 endpoint，這也正是 cron 實際走的路徑：

```bash
curl -X POST "https://<PROJECT_REF>.supabase.co/functions/v1/daily-summary" \
  -H "Authorization: Bearer <SERVICE_ROLE>" -H "Content-Type: application/json" -d '{}'
```

回傳 `sent` 就對了，Telegram 應該立刻收到一則當日總結。

**確認成功**：SQL Editor 跑
`select jobname, schedule, active from cron.job;` 看得到兩筆 `foodlog-*`。

```bash
# 改了 Edge Function
supabase functions deploy telegram-webhook

# 改了 PWA
# ⚠️ 先把 pwa/sw.js 最上面的 VERSION 加一，否則手機會鎖住舊版
```

改前端時可以先在本機看（需要 Deno）：

```bash
deno run --allow-net --allow-read dev/mock-server.ts
```

## 出問題時看哪裡

| 症狀 | 先看哪裡 |
|---|---|
| Bot 完全沒反應 | `curl .../getWebhookInfo` 看 `last_error_message` |
| Bot 回「出錯了」 | Supabase → Edge Functions → telegram-webhook → Logs |
| Edge Function 回 `42501 permission denied` | 步驟 3 的「Automatically expose new tables」被關掉了，跑 `supabase/fix_grants.sql` |
| 照片辨識失敗 | Logs 裡找 `Gemini 4xx`。429＝超過免費層速率，等一分鐘 |
| 手搖數字怪怪的 | Table Editor 開 `drinks` 找那一筆，直接改數字並把 `source_type` 改成 `official` |
| PWA 一直是舊版 | `pwa/sw.js` 的 VERSION 有沒有加一 |
| PWA 說 token 失效 | 用 `/app` 拿網址，或重跑 `select token from report_token;` |
| PWA 打開是「config.js 裡的 API_BASE 還沒填」或完全沒資料 | `pwa/config.js` 還是原作者的 project ref，回步驟 7 換掉 |
